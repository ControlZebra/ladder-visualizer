# L5X FBD Port Metadata Slice (Issues #41 and #63)

- **Capability:** Infer every FBD Block's wireable ports from the decorated structure owned by its operand. Function extensions and Add-On Instructions retain their separate metadata rules; wire participation never supplies port metadata.
- **Public entry points:** `L5XParser.parse`, `L5XParser.parseDocument`, `parseString`, `parseDocumentString`, and the Function-only `FBD_FUNCTION_METADATA` / `resolveBuiltInFBDFunctionMetadata` API. `FBD_INSTRUCTION_METADATA` and the broad built-in resolver remain deprecated aliases for one compatibility cycle.
- **Normalized result and invariants:** Block ports use exact direct-member IDs as labels and retain member data types. `EnableIn` must be the first member; members before `EnableOut`, including `EnableIn`, are inputs, while `EnableOut` and following members are outputs. `VisiblePins` filters those members without changing structure order, and side-local order is compacted. An explicitly empty attribute is a valid zero-port Block; an absent attribute is diagnosed. Nested members are not flattened. Source arrays are preserved without catalog-driven required-array validation. AOI InOut bindings remain separate from wireable Input and Output ports.
- **Supported versions:** The source-derived Block rule is version-independent and is exercised with real-sample-compatible v17 input plus schema-valid v33-v35 fixtures. Function metadata remains gated to Logix major versions v17 through v35 and supported controller families. Schema conformance remains pinned to Studio 5000 v33, v34, and v35.
- **Export envelopes:** Program-owned routines resolve the first matching name from Program tags and then Controller tags. AOI-owned routines resolve AOI LocalTag `DefaultData`. A nearer scope shadows an outer scope; duplicate definitions within one scope are ambiguous.
- **XSD symbols:** `FBD_BlockType`, `FBD_SpecialArrayType`, `FBD_AOIType`, `FBD_AOIArgumentType`, and `AOIParameterType`. `Function` is absent from the v33-v35 schemas, so Function tests remain explicit extension/placeholder behavior and do not expand schema conformance claims.
- **Unsupported or invalid policy:** Missing Block type/operand/visible-pin data, unresolved or ambiguous operands, missing or ambiguous decorated structures, unnamed or duplicate direct members, invalid sentinels, and duplicate or unknown visible pins produce stable diagnostics and canonical placeholders. The parser does not fall back from a tag to another tag or data-type definition with the same data type. Unknown Function mnemonics and unsupported Function controller/version combinations remain diagnosed placeholders.
- **Non-goals:** Data-type fallback, nested-member flattening, wire-based inference, instruction-specific Block catalogs, SVG artwork, live values, Studio 5000 visual cloning, and schema expansion beyond v33-v35.
- **Tests and fixtures:** `tests/parsers/l5x-fbd-port-metadata.test.ts`, `fbd-port-metadata-v33.L5X`, `fbd-port-metadata-v34.L5X`, `fbd-port-metadata-v35.L5X`, the sanitized public level-control sample exercised in its original v17/L63 context, plus existing connected-wire and AOI regressions.
- **Completion commands:** Focused metadata tests, schema validation, conformance, typecheck, lint, full suite, and build.

The original issue #41 Block catalog covered nine level-control mnemonics. Issue #63 removes that catalog dependency: those Blocks, BAND, BOR, AND, SRTP, and future well-formed Blocks all use the same source-derived rule. Function metadata remains limited to ADD, MUL, SUB, and GRT and is additionally gated to supported modern controller families.
