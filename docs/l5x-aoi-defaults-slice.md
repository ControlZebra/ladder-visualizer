# AOI default-data slice (#70)

## Contract

- **Capability and entry points:** `L5XParser.parse`, `parseString`, and `parseDocumentString` expose AOI parameter and local-tag defaults for Studio 5000 exports. Controller and standalone AOI envelopes use the same mapping.
- **Normalized fields:** Each AOI parameter and local tag has optional ordered `defaultData: NormalizedTagData[]`. Decorated entries retain typed atomic, array, and structure nodes recursively, including mixed child order, member order, and element order. AOI local `dimensions` is an ordered array of extents. `defaultValue` remains a scalar shortcut; Decorated `DataValue` wins over L5K or String text. Composite decorated data has no scalar shortcut. `diffControllers` compares parameter and local-tag defaults and reports local-tag additions, removals, and modifications.
- **Schema:** `AOIParameterType` and `AOILocalTagType` contain an optional, repeatable `DefaultData` choice; `Data` permits text plus repeated decorated node choices. `DataArray` has repeated `Element` children, `DataArrayElement` has repeated `Structure` children, and `DataStructure` has repeated atomic, array, and structure member choices. `Dimensions` and `Index` are schema strings. The pinned v33, v34, and v35 definitions are equivalent for these nodes. Local `l5x-schema` commit `441573b4f96493a0fa31627a51b8a4ecb857e980` matches the CI pin.
- **Cases:** Absent defaults remain absent; single and repeated representations retain source order. Decorated arrays, structures, mixed top-level and member order, and arrays of structures normalize. Raw text-only defaults, unknown formats, and unsupported child nodes remain in `defaultData` and source fragments with `UNSUPPORTED_L5X_AOI_DEFAULT_DATA` and `partial` status. Unsafe or malformed local and parameter dimensions produce specific `UNNORMALIZED_L5X_AOI_*_DIMENSIONS` diagnostics. Unrepresentable decorated array dimensions or element indexes, including nested array members, produce `UNNORMALIZED_L5X_AOI_DEFAULT_DATA`. These cases return `partial` and retain the source. The dimension and index probes are schema-valid string mutations, not claimed Studio export shapes.
- **Non-goals:** Decoding raw binary defaults, synthesizing missing array elements, interpreting PLC execution state, and accepting authored L5X as Studio export evidence.

## Export evidence

The `AB-samples` checkout at `68a6a4c05552f9837c95d0bb0accc20c98d7f9e5` contains 67 AOI local-tag Decorated array or structure defaults across its Studio 5000 exports (13 arrays and 54 structures). The reduced [v17 fixture](../tests/fixtures/l5x/aoi-defaults-v17.L5X) uses the following shapes from `Add_On_Instructions_Samples.L5X` (Studio 5000 `17.00`, `TargetType="Controller"`): `DeltaT/CurrentTS` array and `LoopSimulation/DEDT_01` structure. It also uses the array-of-structures shape from `Kinematics_Delta_3D_with_PickPlace_AOI.L5X` (Studio 5000 `17.00`, `TargetType="Controller"`), `PICKPLACE/InstTracker`. The fixture removes project metadata, routines, unrelated tags, and most members/elements; its names and representative values remain only where needed to trace the exported shape. The v17 fixture is parser evidence; no matching v17 XSD is present, so no XSD validation is claimed for it. A repository scan found no AOI **parameter** composite default in this corpus; parameter mapping is tested with XSD-valid v33–v35 fixtures using the same `DefaultData` type.

The v33–v35 `normalization-coverage` fixtures validate against their matching XSDs. They exercise parameter arrays, local multidimensional arrays, local structures, mixed top-level Decorated choices, and (in v35) interleaved atomic, array, and structure members. The mixed-choice form is a schema-valid ordering probe, not a claimed Studio export shape. The `aoi-v33`–`v35` fixtures retain scalar L5K and missing-default compatibility. Unsupported and invalid forms are focused parser tests rather than claimed export examples.
